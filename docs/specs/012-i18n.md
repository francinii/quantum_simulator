# Internationalization (English and Spanish)

Status: draft

## Goal

Every user-facing text is available in English and Spanish, and the visitor can switch language at any time. English stays the source and default language; Spanish is a full translation.

## Behavior

### Language selection

- Locales: `en` (source, fallback) and `es`.
- Initial locale: the stored choice, else the first match of `navigator.languages` (`es-*` maps to `es`), else `en`.
- The choice persists in `localStorage` (`quantum-lab:locale`); storage failures fall back to detection.
- Switching is instant, with no reload and no route change. `<html lang>` is updated to match.
- The switcher lives in the sidebar footer (see `010-sidebar-navigation.md`): a labeled control with "English" and "Español" (each shown in its own language), keyboard operable.
- The URL does not carry the locale (no `/es/...`). The site is static, has no SEO need today, and this keeps routes simple. Revisit if landing pages need indexed Spanish URLs.

### Message catalogs

- Library: **`i18next` + `react-i18next`**, with `i18next-browser-languagedetector` for the initial locale. The stack table in `CLAUDE.md` gets an "i18n" row.
- Strings live in typed resource files, one pair per owner, each owner being an i18next **namespace**, following the feature-driven structure:
  - `shared/i18n/en.ts`, `es.ts`: namespace `shell` (menu, layout, common buttons, errors, not-found, coming-soon).
  - `features/<name>/i18n/en.ts`, `es.ts`: that feature's namespace. Exposed through the feature's `index.ts`; the app aggregates them (same glob mechanism as simulator configs) and registers them with i18next, so features never import each other.
- `en` defines the shape. `es` is typed against it, so a missing or extra key is a compile error. Key typing for `t()` comes from i18next's `CustomTypeOptions` augmentation built from the `en` resources, so a wrong key in a component is also a compile error.
- Keys are named by meaning, not by English wording (`nav.lab`, `title`).
- `fallbackLng: 'en'`: a key missing in `es` shows the English text (and logs in development), so partial translation is safe.
- Components call `useTranslation('<namespace>')` and `t('key')` / `t('key', { name })` with `{{name}}` interpolation. Plurals use i18next's built-in plural rules; numbers and dates use `Intl` with the active locale. No text literals in JSX or in configs.
- Simulator configs no longer hold `title`, `description` or `category`: they live in the simulator's own namespace (named after its `id`) under those three keys, read through `useSimulatorText(id)`. The `chip` is notation, so it stays in the config. The gallery stays generic.
- Page-level copy (Lab header, coming-soon pages, not-found, load errors) lives in the `shell` namespace; the gallery card labels live in the `gallery` namespace.
- The switcher is `LanguageSwitcher` in the sidebar footer, above the theme switcher; in the icon-only rail it becomes one button that cycles the language. The browser tab title (`documentTitle`) is translated too.
- Detection order: `localStorage` (`quantum-lab:locale`), then `navigator`; `supportedLngs: ['en', 'es']` with `load: 'languageOnly'` so `es-MX` resolves to `es`.
- Catalogs are bundled, not lazy-loaded, while there are only two languages and small catalogs.

### What is and is not translated

- Translated: all UI copy, labels, tooltips, `aria-label`s, document titles, error and empty states, GIF-export status text, file names of exports, and text drawn on canvas or SVG.
- Not translated: mathematical notation, Dirac notation, gate names and symbols (H, CNOT, |0>, ...).
- Spanish terminology follows a single glossary so the same concept is always named the same way:

| English        | Spanish           |
| -------------- | ----------------- |
| qubit          | qubit             |
| superposition  | superposición     |
| entanglement   | entrelazamiento   |
| measurement    | medición          |
| gate           | compuerta         |
| decoherence    | decoherencia      |
| interference   | interferencia     |
| Bell states    | estados de Bell   |
| Bloch sphere   | esfera de Bloch   |
| amplitude      | amplitud          |
| matrix algebra | álgebra matricial |

The glossary grows with the content; the Learn spec will own the full version.

### Long-form content

- Articles and Learn content is authored per locale (separate content files per language), decided in their own specs. If a piece has no Spanish version yet, it shows in English with a visible "available in English only" notice.

### Layout

- Spanish text is typically 15-25% longer. Components must wrap or grow rather than truncate; the longest menu label must fit the expanded sidebar.

## Phasing

Progress: phase 1 is implemented; phases 2 and 3 are pending.

1. Infrastructure and shell: i18next setup, catalogs, switcher, menu, layout, coming-soon, not-found, gallery.
2. Simulators, one at a time, each translated as part of its own acceptance. Untranslated simulators fall back to English per key until done.
3. Articles and Learn: translated as they are written.

## Decisions

- `react-i18next` over in-house catalogs (decided by the owner): mature plurals, interpolation, detection and ecosystem, at the cost of three dependencies. Type safety is kept through the typed resources described above.
- Glossary terms confirmed: "medición" (not "medida") and "compuerta" (not "puerta").
- The Spanish copy gets a native review before each release that includes new Spanish text.

## Out of scope

- Languages beyond `en` and `es`, right-to-left layouts.
- Locale in the URL, server-side detection.
- Machine translation at runtime.
- Translating `legacy/`.

## Acceptance criteria

- [x] Initial locale follows stored choice, then browser language, then `en`; the choice persists.
- [x] Switching language updates all visible text and `<html lang>` instantly, without reload.
- [x] A key missing in `es` fails type checking; a runtime miss falls back to English.
- [x] No user-facing literal strings remain in `shell`, `gallery` and layout components (phase 1).
- [ ] Menu, coming-soon, not-found and gallery render fully in both languages; the longest label does not overflow at 360px or in the expanded sidebar.
- [x] Simulator configs reference message keys; adding a simulator needs no gallery change.
- [x] A test asserts `es` and `en` catalogs have identical keys and no empty values.
- [x] Math notation and gate symbols are identical in both languages.
- [ ] Switcher is keyboard operable and labeled; works in the sidebar rail and mobile drawer.
- [x] `i18next`, `react-i18next` and the language detector are added and `CLAUDE.md` lists them in the stack.
- [x] Unit tests cover detection, persistence, interpolation and fallback; lint, format, tests and build pass.
